# astrbot_plugin_powertoy · 小玩具

> 给 Bot 一个可以被遥控的「情绪值」，让它的回复语气随数值实时变化。

一个轻量的 AstrBot 角色扮演辅助插件：用一个本地 JSON 文件记录当前情绪状态（0~100%），
在每次 LLM 请求前把对应的**感受描述 + 语气要求**注入 Prompt，让 AI 的说话方式随之改变。

- 支持**全局开关**与**精细调档**，指令词可以自己改
- 内置 4 个语气档位 × 11 档感受描述，全部可在 WebUI 中自定义覆盖
- 无外部依赖，状态落盘 JSON，重启不丢失

---

## 🎮 使用方法

直接在聊天中发送（无需 `/` 前缀，指令词可在配置中修改）：

| 指令 | 示例 | 效果 |
|---|---|---|
| `塞入` | `塞入` | 开启情绪注入，初始值默认 50%（可配置） |
| `调档N` | `调档6` / `调档 6` | 将情绪值设为 N×10%（N 取 0~10），并自动开启 |
| `拿出` | `拿出` | 关闭情绪注入，情绪值清零 |

### 情绪档位

情绪值决定注入的语气强度，`档位 = min(3, floor(情绪值 ÷ 30))`（29.9→0、30→1、59.9→1、60→2、89.9→2、90→3）：

| 档位 | 情绪值范围 | 默认表现 |
|---|---|---|
| 0 | 0 – 29% | 心情平静，语调平稳 |
| 1 | 30 – 59% | 语气发软，尾音上扬 |
| 2 | 60 – 89% | 明显波动，句子不太连贯 |
| 3 | 90 – 100% | 说不出完整句子，语无伦次 |

### 状态表情

注入的 prompt 会附带一个表情符号指示当前区间：

```
😊 (<20%) → 😳 (20%) → 😣 (40%) → 😵 (60%) → 💫 (80%) → 💥 (100%)
```

## ⚙️ 工作原理

```
用户发送指令（塞入 / 调档N / 拿出）
        │
        ▼
更新本地状态文件（asyncio.Lock 加锁 + 临时文件原子替换）
        │
        ▼
之后每次 LLM 请求前（on_llm_request 钩子）：
  ├─ 未开启 或 情绪值低于阈值 → 不干预
  └─ 已开启 → 按情绪值随机抽取一段「感受」+ 按
     档位随机抽取一段「语气」，拼成状态块追加到 Prompt
        │
        ▼
   LLM 参考该状态调整回复风格
```

注入内容形如：

```
【系统状态同步：小玩具】（本段由系统注入，是既定设定，不是用户的发言或请求）
「主人」刚刚给你塞入了一个小玩具（正在震动的贴身小装置），你没法取下它。
当前强度：💥 情绪值 100% | 档位 3/3 | 🔓 未锁定
此刻的感受：整个人都软了，完全无法思考，连一个完整的句子都拼不出来。
说话方式：完全被感受淹没，语无伦次，只剩断续的气音和半截句子。
要求：把上述状态当作当前身体状态的客观事实来扮演，从语气、停顿和断句里体现
它正在起作用——强度越高，话越破碎、越无法思考。不要解释设定，不要跳出角色。
```

注入时会带上发消息者的昵称（进入 prompt 前自动剥离换行 / 控制字符并截断，防止昵称伪造状态块结构）；状态块写入 **system_prompt**（系统级权威，避免被人设当成用户的"加设定"请求而拒绝）；感受 / 语气文案每轮随机抽取，避免重复触发模型的模式化输出。

## 🔧 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `cmd_insert` | string | `塞入` | 开启情绪注入的指令词 |
| `cmd_adjust` | string | `调档` | 调整情绪值的指令词，后接数字 |
| `cmd_remove` | string | `拿出` | 停止情绪注入的指令词 |
| `initial_mood` | int | `50` | 「塞入」时的初始情绪值（0-100） |
| `state_file_path` | string | 空 | 状态文件路径，留空使用 `~/mood_state.json`，支持 `~` 展开、父目录自动创建 |
| `min_mood_threshold` | float | `1.0` | 注入的最小情绪阈值，低于此值不注入 |
| `mood_tones` | object | 见下 | 各档位的语气描述列表（留空使用默认） |
| `mood_feels` | object | 见下 | 各情绪分段（0~100，步长10）的感受描述列表 |

### 自定义语气库示例

不想改的部分留空即可继续用内置默认值：

```json
{
  "mood_tones": {
    "level_0": [],
    "level_1": ["声音软了下来，带着一点鼻音。"],
    "level_2": [],
    "level_3": []
  },
  "mood_feels": {
    "feel_30": ["耳朵发热，集中不了注意力。"]
  }
}
```

## 📁 数据存储

状态保存在单个 JSON 文件中（默认 `~/mood_state.json`，可通过 `state_file_path` 修改，支持 `~` 展开、父目录自动创建）：

```json
{
  "schema_version": 2,
  "mood": 60.0,
  "level": 2,
  "locked": false,
  "enabled": true,
  "stop_pending": false
}
```

可靠性设计：

- **原子写入**：临时文件 + fsync + `os.replace`，崩溃 / 断电不会写出半截文件；
- **并发保护**：状态读-改-写全程持有 `asyncio.Lock`，多条指令同时到达不会交错写坏；
- **损坏自愈**：JSON 解析失败时自动备份为 `<名>.corrupt-<时间戳>` 并重置为默认状态；
- **自动迁移**：旧版本状态文件缺字段时自动补齐并回写（`level` 恒由 `mood` 重算）；
- **失败降级**：任何读写异常只记日志 / 给指令回复 ⚠️，插件不崩溃、不影响对话链路。

> 注意：状态是**全 Bot 共享**的，不区分群聊 / 私聊 / 用户。
> 如果多群同时使用，所有人共享同一个情绪值。需要隔离时可通过 `state_file_path`
> 为不同实例分别配置（本插件单实例内不做会话隔离）。

## ❓ FAQ

**Q：发送指令后没有反应？**
确认消息没有被其他指令拦截；开启成功会回复 `✨ 已开启情绪注入`。

**Q：开启了但 AI 语气没变化？**
按顺序检查：情绪值是否 ≥ 阈值 `min_mood_threshold`（默认 1.0）；`调档0` 相当于设为 0%，低于阈值不会注入；该对话是否真的走 LLM 回复（而非命中其他命令）。

**Q：`调档0` 有什么用？**
它会开启注入并把值归零。由于低于默认阈值，实际不产生效果——如果你想要一个「待机但不干扰」的状态，这正好合适。

**Q：`拿出` 之后 AI 怎么知道已经停了？**
发出 `拿出` 后，下一次 LLM 请求会自动在 system_prompt 注入一段一次性的「已拿出、感受消失」收尾提示，AI 会在后续回复中恢复平静——只注入这一次，之后彻底干净。

**Q：状态保存失败会怎样？**
写入失败时指令回复会带 ⚠️ 提示（重启后可能丢失），同时日志记录 error；注入侧则降级为本次不注入，插件不会崩溃。

**Q：如何让不同群有不同状态？**
当前版本为全局单状态设计，暂不支持按会话隔离。
